## Commands

```bash
bun dev          # Start dev server on port 3000
bun build        # Production build
bun test         # Run tests (Vitest)
bun run machine-translate  # Auto-translate missing i18n messages
bun run reverify-payments  # Re-verify stuck OnlinePayment rows against maib (fallback for missed webhooks)
```

Prisma commands must be prefixed with `bun --bun run prisma`:
```bash
bun --bun run prisma migrate dev   # Run migrations
bun --bun run prisma generate      # Regenerate Prisma client
bun --bun run prisma studio        # Open DB GUI
```

## Architecture

This is a full-stack SSR app built with **TanStack Start** (Vite + React 19), using **Bun** as the runtime and package manager.

### Routing

File-based routing via **TanStack Router**. `src/routeTree.gen.ts` is auto-generated — never edit it manually. Route conventions:
- `_public/` — layout group for unauthenticated pages
- `admin/` — protected admin area
- `api/auth.$.ts` — better-auth catch-all handler
- `api/rpc.$.ts` — oRPC API endpoint

### API Layer (oRPC)

Type-safe RPC over HTTP at `/api/rpc`. The pattern:

1. **`src/features/shared/orpc/base.ts`** — defines the base `os` builder with context `{ headers: Headers }` and optional `{ anonymous?: boolean }` metadata
2. **Feature routes** live in `src/features/<feature>/routes/` — each file exports a route built from a feature-scoped base (adds tag/path prefix)
3. **`src/features/shared/orpc/router.ts`** — composes all feature routes into `orpcRouter`
4. **`src/lib/orpc/client.ts`** — isomorphic client: uses `createRouterClient` on the server (direct call, no HTTP), `createORPCClient` + `RPCLink` in the browser. Import `orpc` from here for TanStack Query utilities.

Routes that require auth check permissions via middleware in the feature base. Routes opt out of auth with `meta({ anonymous: true })`.

### Database (Prisma + PostgreSQL)

Schema is split across `prisma/models/*.prisma` files and merged by `prisma.config.ts`. Generated client outputs to `prisma/generated/prisma/`. The Prisma client singleton is in `src/lib/db/` with `prisma-extension-pagination` and a slow query logger extension.

### Authentication (better-auth)

- Server config: `src/lib/auth/better-auth.ts` — Prisma adapter, admin plugin, openAPI plugin
- Browser client: `src/lib/auth/better-auth-client.ts` — `authClient` with `adminClient` plugin
- **RBAC**: `src/lib/auth/permissions.ts` defines `statements` (extending better-auth defaults with a `categories` resource), and roles `user`/`admin`. Permissions are checked via `authClient.admin.checkRolePermission` or server-side middleware.
- Two roles: `user` (limited category access) and `admin` (full access including all better-auth admin operations)

### i18n (Paraglide)

- Base locale: Romanian (`ro`), secondary: Russian (`ru`)
- Message files: `messages/{locale}.json`
- Generated runtime: `src/paraglide/` — **do not edit**; regenerated by the Vite plugin on `bun dev`/`bun build`
- Usage: `import { m } from '@/paraglide/messages'` then call `m['key.name']()`
- Strategy: cookie (`lang`) → browser preference → URL → base locale
- To add a new key: add it to `messages/ro.json`, then run `bun run machine-translate` to populate other locales

### UI Components

Shadcn UI (`components.json` config). Components live in `src/components/ui/`. Add new shadcn components via the CLI per `components.json` settings. Data tables use TanStack Table wrappers in `src/components/data-table/`.

### Online payments (maib)

MAIB confirms payment completion via a signed webhook to `/api/orders/online-payment-callback`, verified in `src/features/orders/common/services/maib-client.ts`. That webhook can be missed (unreachable on localhost, or delayed/dropped in prod), so stuck `OnlinePayment` rows are re-verified against maib by `OnlinePaymentService.reverifyPending()`. Two ways to run it:

- **In-process interval (default):** `OnlinePaymentService.startReverifyJob()` is called from `src/server.ts` at boot and runs `reverifyPending()` on a timer when `REVERIFY_PAYMENTS_ENABLED=true` (default `false`). Interval length is `REVERIFY_PAYMENTS_INTERVAL_MINUTES` (default `5`). Runs one pass immediately on boot, then every interval; skips a tick if the previous one is still running.
- **External cron fallback:** `scripts/reverify-online-payments.ts` (`bun run reverify-payments`) runs one pass and exits — useful where the app process is short-lived or the in-process timer is disabled:
```
*/5 * * * * cd /path/to/app && bun run reverify-payments >> /var/log/reverify-payments.log 2>&1
```
